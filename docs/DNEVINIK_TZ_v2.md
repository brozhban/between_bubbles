## 1. Термины

- **Запись (дегустация, `TastingEntry`)** — один факт употребления конкретного вина в конкретный день.
- **Вино (`Wine`)** — карточка вина в личном справочнике пользователя. Одно вино может иметь несколько записей (повторные дегустации).
- **Неделя (`Week`)** — календарная неделя Пн–Вс в таймзоне пользователя.
- **Бокал** — 150 мл. Бутылка — 750 мл = 5 бокалов.

## 2. Роли и доступ

| Роль | Права |
|---|---|
| Гость | Публичные страницы сайта, регистрация, вход, просмотр расшаренной карточки вина по ссылке |
| Пользователь | Полный доступ **только к своим** данным: записи, вина, недели, фото, настройки, экспорт, удаление аккаунта |
| Администратор | Модерация общего справочника магазинов (слияние дублей, скрытие мусора), просмотр системных метрик. Доступ к дневникам пользователей отсутствует |

**Изоляция данных (обязательное требование).** Каждая пользовательская сущность содержит `userId`. Доступ реализуется так:

1. Единый слой репозиториев: ни один запрос к пользовательским таблицам не выполняется без явного `where: { userId }`. Прямые вызовы Prisma в обход слоя запрещены архитектурной проверкой.
2. Все `findUnique`/`findFirst` по id дополнительно проверяют владельца; при чужом id возвращается **404**, а не 403 (не раскрываем существование записи).
3. Интеграционные тесты «чужой пользователь»: для каждого эндпоинта — кейс, где второй пользователь пытается получить/изменить/удалить объект первого. Прохождение этих тестов — критерий приёмки.
4. Опциональное усиление (этап 2): PostgreSQL RLS с `app.current_user_id`, выставляемым в транзакции.

  defaultCurrency Currency @default(GEL)

  emailVerifiedAt DateTime?

  producer       String?
  originCountry  String?   @db.Char(2)     // ISO 3166-1 alpha-2, страна происхождения

// ---------- Запись о дегустации ----------
model TastingEntry {

model EntryAroma {          // множественный выбор тегов

// ---------- Фото ----------

// ---------- Общий справочник магазинов ----------

| Код | Название |
|---|---|

## 5. Справочники

### 5.1 Страны
Полный список ISO 3166-1 alpha-2, названия локализованы под язык интерфейса (ru/en), в списке — флаг + название. Используется в двух полях: страна покупки и страна происхождения вина.

### 5.2 Магазины — общий справочник с защитой от мусора

Пополняется пользователями без предварительной модерации, но с тремя слоями защиты:

1. **Нормализация и дедупликация при вводе.** `normalizedName` = lowercase + trim + схлопывание пробелов + удаление пунктуации. Перед созданием — нечёткий поиск (триграммы, `pg_trgm`) по стране/городу. При сходстве ≥ 0.6 показывается подсказка: «Возможно, вы имели в виду: *Goodwill*» с кнопками «Да, это он» / «Нет, создать новый».
2. **Привязка к контексту.** У магазина обязательна страна, опционально город и тип (супермаркет / винотека / ресторан / бар / онлайн / другое). Автодополнение сначала предлагает магазины страны, выбранной в поле «страна покупки», затем — личные недавние (`UserStoreRecent`), затем остальные по `usageCount`.
3. **Постмодерация.** В админке: список новых магазинов, слияние дублей (`MERGED` + `mergedIntoId`, все записи перецепляются на мастер), скрытие мусора (`HIDDEN` — перестаёт предлагаться, но остаётся в старых записях). Плюс антиспам: не более 10 новых магазинов от одного пользователя в сутки, минимальная длина 2 символа, блокировка ссылок и разметки в названии.

### 5.3 Теги аромата
Системные 7 тегов доступны всем. Свои теги пользователь создаёт **в личном пространстве** (`AromaTag.userId`), в общий справочник они не попадают — это осознанно снимает проблему модерации, которая есть у магазинов.

## 6. Неделя: жизненный цикл

- Неделя — **календарная, Пн–Вс**, границы вычисляются в таймзоне пользователя (`User.timezone`, определяется из браузера при регистрации, меняется в настройках).
- Неделя **создаётся автоматически** при сохранении первой записи с датой, попадающей в неё. Кнопки «создать неделю» нет.
- Понятия «архив» нет: все недели равноправны и доступны листанием назад/вперёд. Кнопки «завершить неделю» нет.
- Прошлые недели **полностью редактируемы**: можно добавить забытую запись, изменить и удалить существующую.
- Дата записи определяет неделю: запись с прошлой датой уходит в **свою** прошлую неделю, а не в текущую. При изменении даты запись автоматически переезжает между неделями (и, при необходимости, создаёт целевую неделю).
- Дата в будущем **запрещена** (валидация на клиенте и на сервере, «будущее» определяется по таймзоне пользователя).
- Пустая неделя показывает заголовок, календарь без бокалов и empty-state «На этой неделе записей нет» + кнопка «Добавить вино». Метрики и диаграммы скрыты.
- Неделя, в которой нет записей, в БД не создаётся (нет мусорных строк при листании).

## 7. Запись о дегустации

### 7.1 Обязательные и опциональные поля

**Обязательные:** дата, название вина, тип вина, рейтинг, количество выпитого.
**Все остальные поля опциональны** — включая цену, валюту, фото, страну, магазин, характеристики, категорию вкуса, заметки.

Правило связности: если указана цена — валюта обязательна (по умолчанию подставляется валюта из профиля).

### 7.2 Количество выпитого

Хранится в миллилитрах. В интерфейсе — быстрые кнопки в стиле прототипа плюс ручной ввод:

| Кнопка | мл | бокалов |
|---|---|---|
| 🍷 | 150 | 1 |
| 🍷🍷 | 300 | 2 |
| 🍷🍷🍷 | 450 | 3 |
| 🍾 бутылка | 750 | 5 |
| «Другое» | ручной ввод мл | мл / 150 |

Бокалы во всех метриках = `volumeMl / 150`, округление до 0.5 при отображении.

### 7.3 Рейтинг

Шкала **0.5 – 5.0 с шагом 0.5** (10 значений), ноль невозможен. Компонент — 5 звёзд с половинками; на мобильном тап по левой/правой половине звезды. Отображение: `★★★★☆` + числовое значение.

### 7.4 Цена

Цена указывается **за бутылку** и относится к покупке, а не к выпитому объёму. Поэтому:

- цена не делится на бокалы и не умножается на количество записей;
- если пользователь допивает ту же бутылку на следующий день, он нажимает **«Та же бутылка»** и выбирает предыдущую запись → новая запись получает `sameBottleOfId`, поля вина/цены/валюты/магазина копируются и **помечаются как повтор**;
- при суммировании трат записи с `sameBottleOfId ≠ null` **не учитываются** — бутылка считается один раз;
- цена может быть не указана вовсе (бокал в ресторане, подарок, дегустация) — такая запись не участвует в денежных метриках, но полноценно участвует во всех остальных.

### 7.5 Повтор вина

Кнопка **«Уже пробовал»** открывает личный справочник вин: выбрав вино, пользователь получает предзаполненную карточку (название, производитель, страна, сорт, винтаж, тип, сахар) и заполняет заново только впечатления — рейтинг, аромат, заметки, ощущение. Это отдельная новая запись, история дегустаций вина сохраняется целиком.

### 7.6 Редактирование и удаление

- Редактирование доступно всегда, в любой неделе.
- Удаление **мягкое**: запись уходит в «Корзину» (`deletedAt`), исключается из всех метрик и списков.
- В Корзине: восстановление и «Удалить навсегда»; кнопка «Очистить корзину». Автоочистка через 30 дней.
- Окончательное удаление записи удаляет её фото из хранилища.
- Удаление вина из справочника возможно только если у него нет активных записей.

## 8. Формулы расчётов

Все метрики считаются **на лету** по активным (`deletedAt = null`) записям недели. Кэширование — не раньше, чем появится реальная проблема производительности.

### 8.1 Метрики недели

| Метрика | Формула | Поведение при нехватке данных |
|---|---|---|
| Всего вин | количество активных записей недели | 0 → блок метрик скрыт |
| Бокалов за неделю | `Σ volumeMl / 150`, до 0.5 | 0 |
| Мл за неделю | `Σ volumeMl` | 0 |
| Топовое вино | запись с максимальным `rating`. **При равенстве показываются все лидеры** (список, сортировка по дате дегустации) | нет записей → блок скрыт |
| Самая частая категория вкуса | мода по `tasteCategory` среди записей, где она заполнена. **При ничьей показываются все лидеры** через запятую | ни у одной записи нет категории → «—» |
| Распределение по типу вина | доли `WineType` по количеству записей | 1 запись → круг из одного сектора, показываем как есть |
| Распределение по категориям вкуса | доли `TasteCategory`; записи без категории идут в сегмент «Без категории» | — |
| Траты по валютам | `Σ price` по каждой валюте отдельно, **исключая записи с `sameBottleOfId`**. Валюты не смешиваются и не конвертируются. Блок показывается, только если `showSpendTotals = true` | нет цен в валюте → валюта не показывается |

Денежные значения отображаются округлёнными до целых, с символом/кодом валюты.

### 8.2 Что удалено из ТЗ v1

- **Настроение после дегустации** — поле удалено из модели данных целиком. Вместе с ним удалены: бонус настроения в выборе топового вина (топовое вино определяется только рейтингом), эмодзи настроения в календаре недели, линейный график настроения, динамика настроения в статистике за период.
- **Средний рейтинг недели** — удалён. Усреднение оценок разных вин признано некорректным. Средний рейтинг считается только **у конкретного вина** по всем его дегустациям и показывается в карточке вина и в списке «Мои вина».
- **Вино с лучшим соотношением цена/качество** («самое выгодное вино») — метрика удалена целиком.
- **Средняя стоимость вина за неделю** — заменена на опциональные суммарные траты по валютам (п. 8.1), включаемые пользователем в настройках.

## 9. Визуализации

| Блок | Правила |
|---|---|
| **Календарь недели** | 7 ячеек Пн–Вс. В каждой: количество иконок 🍷 = **число записей** этого дня. День без записей — пустая ячейка |
| **Столбчатая диаграмма по дням** | Переключатель «Вина / Бокалы»: по количеству записей или по сумме бокалов за день |
| **Круговая: типы вина** | 4 сектора, фиксированные цвета за типом (белое / красное / розовое / оранж) |
| **Круговая: категории вкуса** | 6 категорий + «Без категории» |

Все диаграммы адаптивны, читаемы в тёмной теме, при одной записи отображаются как есть (без спецобработки).

## 10. Экраны

### `website` (публичный)
1. **Лендинг** — что такое Дневиник, 18+ дисклеймер, кнопки «Войти» / «Зарегистрироваться».
2. **Публичная карточка вина** `/w/{slug}` — фото, название, звёзды рейтинга, категория вкуса, заметки, при включённой опции — имя автора. Мета-теги OG для превью в мессенджерах, `noindex, nofollow` по умолчанию.
3. **Оферта, политика конфиденциальности, контакты.**

### `webapp` (за логином)
4. **Регистрация / вход / восстановление пароля / подтверждение email.** В регистрации — дата рождения (проверка 18+) и согласие с офертой.
5. **Неделя (главный экран)** — шапка с диапазоном дат и стрелками «‹ предыдущая / следующая ›», кнопка «Сегодня»; блок сводных метрик; календарь; диаграммы; таблица записей с миниатюрами; плавающая кнопка «+ Добавить вино».
6. **Форма записи** — пошаговая на мобильном (Основное → Характеристики → Впечатления), одностраничная на десктопе. Загрузка до 2 фото, выбор валюты рядом с ценой, автодополнение страны и магазина, кнопки «Уже пробовал» и «Та же бутылка».
7. **Карточка вина** — данные вина, средний рейтинг вина, все дегустации, фото.
8. **Мои вина** — список всех вин пользователя: миниатюра, название, тип, средний рейтинг, число дегустаций, дата последней. Фильтры: **тип вина и рейтинг** (диапазон), плюс поиск по названию. Сортировка: по дате, по рейтингу, по алфавиту.
9. **Статистика за период** — переключатель месяц / год / всё время: количество вин и бокалов, топ-5 вин по рейтингу, распределение по типу и категории вкуса, распределение по странам и сортам, динамика количества вин и бокалов по неделям, траты по валютам (если включены).
10. **Корзина** — удалённые записи, восстановление, полное удаление, очистка.
11. **Настройки профиля** — имя, аватар, язык (ru/en), тема (светлая/тёмная/системная), таймзона, валюта по умолчанию, тумблер «Показывать суммарные траты», экспорт данных (CSV/JSON), смена пароля, удаление аккаунта.

### Админка (этап 2)
12. **Справочник магазинов** — новые записи, поиск дублей, слияние, скрытие.

## 11. Фотографии

- До **2 фото** на запись: бутылка и этикетка. Фото опциональны.
- Форматы: **JPG, PNG, WebP, HEIC/HEIF** (без HEIC ломаются загрузки с iPhone). Максимум **10 МБ** до сжатия.
- Клиент сжимает изображение до **1600 px** по длинной стороне и конвертирует HEIC → JPEG перед отправкой; сервер валидирует MIME по сигнатуре файла, а не по расширению.
- **EXIF вырезается полностью** на сервере, включая GPS-координаты. Сохраняется только ориентация (применяется к изображению и удаляется из метаданных).
- Хранение: приватный бакет DigitalOcean Spaces, ключи вида `users/{userId}/entries/{entryId}/{photoId}.jpg`. Публичного доступа к бакету нет.
- Отдача: миниатюра 400 px и полноразмерная версия по **подписанным URL с TTL 5 минут**, выдаваемым только владельцу. Для публичной карточки вина фото отдаётся через backend-прокси, проверяющий действующий `ShareLink`.
- Удаление записи из корзины навсегда удаляет и файлы; удаление аккаунта — все файлы пользователя.
- Съёмка сразу с камеры — этап 3 (мобильное приложение).

## 12. Публикация карточки вина

- Пользователь может поделиться **отдельной записью**: кнопка «Поделиться» создаёт ссылку `/w/{slug}` со случайным неугадываемым slug.
- В публикацию попадают: фото, название вина и его атрибуты, рейтинг, категория вкуса, заметки, ощущение. **Не попадают**: цена, магазин, email, другие записи, любая статистика.
- Тумблер «показывать моё имя» — по умолчанию выключен.
- Ссылку можно отозвать в любой момент (`revokedAt`) → страница отдаёт 404.
- Публикация дневника целиком или недели целиком — не предусмотрена.

## 13. Нефункциональные требования

- **Mobile-first**, адаптив от 360 px; десктоп — расширенная раскладка. PWA: манифест, иконки, установка на домашний экран, offline-заглушка (полноценный офлайн-режим — не в MVP).
- **Темы:** светлая и тёмная, переключение вручную + режим «системная».
- **i18n:** ru/en, включая названия стран, дни недели, форматы дат и чисел.
- **Авторизация:** хеширование паролей современным алгоритмом (argon2id/bcrypt), JWT access + refresh с ротацией и семейством токенов (механизм шаблона), httpOnly cookie. Минимальная длина пароля 8 символов с проверкой на компрометацию по спискам. Подтверждение email, восстановление пароля по одноразовой ссылке (TTL 1 час).
- **Rate limiting:** вход, регистрация, восстановление пароля, создание магазинов, загрузка файлов.
- **Валидация:** единые Zod-схемы из `packages/contracts` на клиенте и сервере. Сервер никогда не доверяет клиентской валидации.
- **Производительность:** первый экран недели ≤ 1.5 с на 4G, расчёт метрик недели ≤ 100 мс на сервере при 100 записях.
- **Тесты:** интеграционные на API (включая кейсы изоляции пользователей), unit на все формулы п. 8, Playwright E2E на сценарии «регистрация → первая запись → метрики недели» и «повтор вина → та же бутылка → траты не задвоились».
- **Бэкапы:** ежедневные автоматические бэкапы Managed PostgreSQL с PITR (входит в тариф) + еженедельный логический дамп в отдельный бакет Spaces с ретенцией 30 дней. Для Spaces включается версионирование объектов. Восстановление проверяется вручную после запуска и далее раз в квартал.
- **Мониторинг:** алерты на 5xx и на недоступность БД, логи ошибок бэкенда.

## 14. Правовые требования

- **18+.** При регистрации указывается дата рождения; пользователи младше 18 не регистрируются. На лендинге — возрастной дисклеймер и предупреждение о вреде алкоголя. Требование обязательно и для будущей публикации в App Store / Google Play (категория 17+/18+, отдельные правила по алкоголю).
- Оферта и политика конфиденциальности публикуются до запуска, согласие фиксируется чекбоксом при регистрации (с датой и версией документа).
- **Экспорт данных:** пользователь может выгрузить свои записи в **CSV и JSON** (генерация асинхронная, ссылка на скачивание с TTL).
- **Удаление аккаунта:** удаляются все записи, вина, фото и персональные данные. Реализация: мягкое удаление + фоновая полная очистка через 30 дней (окно на восстановление по обращению), после чего данные невосстановимы. Записи в общем справочнике магазинов обезличиваются (`createdByUserId = null`), сами магазины остаются.
- Приложение не даёт медицинских рекомендаций и не поощряет потребление; формулировки интерфейса нейтральные.

## 17. Открытые вопросы

1. **Средний рейтинг недели.** В прототипе он есть («средний рейтинг: 4.6»), но по вашему решению усреднять оценки разных вин нельзя — метрика удалена. Заменить её на гистограмму «распределение оценок за неделю» или оставить шапку недели без рейтинга совсем?
2. **Топовое вино при равных рейтингах.** После удаления настроения ничьи станут частыми: три вина по 5.0 — обычная неделя. Заложен показ **всех лидеров** списком. Альтернатива — брать одно, самое раннее по дате. Подтвердите вариант.
3. **Ощущение послевкусия** (баланс / лёгкое / насыщенное / тяжёлое) остаётся — это отдельное поле, не то же самое, что удалённое настроение. Подтвердите, что его не трогаем.
4. **Свои теги аромата** я сделал личными, а не общими — чтобы не повторять проблему модерации магазинов. Согласны?
5. **Домен и slug проекта** — нужны для установки шаблона и настройки деплоя (CORS, `VITE_API_URL`, `PUBLIC_WEBAPP_URL`).
6. **Правообладатель** — приложение выпускается от ИП Химичева Е.Ю. (как в футере таблицы)? От этого зависят реквизиты в оферте и политике.
